# 弦间 · Stringspace

将音乐或视频文件转换成可编辑、可试听、可打印的吉他伴奏六线谱。中文网页界面，不需要 API Key 或订阅。提供 **GitHub Pages 浏览器版** 和 **Python 本机版**。

## v2：先验证转录，不把功能测试当成准确率

用户用分离后的《爱河》吉他音轨复测，发现 v1 播放与原音差异很大。原因是 v1 只估计和弦，再套固定伴奏型，并没有转录原音符和原节奏；固定 BPM 还会积累对齐偏差。此前“生成了谱、接口测试通过”不足以说明转录可靠。

网页版现在默认 **原伴奏转录 · 实验**：使用 Spotify Basic Pitch 预训练模型检测音符、起音和持续时间，映射到标准调弦六线谱，并尽量保留实际时间。局部强起音用于调整小节网格，试听和 MIDI 使用真实检测时间。变调夹只改变弦位，不改变检测到的实际音高。不会为了符合和弦标签而重写音符。

**结果仍是待校对草稿，不保证任意音频可靠。** 模型可能漏音、把泛音识别为音符、将一个持续音切成多次起音；自动弦位也可能不符合原演奏。页面显示未映射音符，导出文件标为草稿。指型冲突会截短同弦余音；丢失较多低音的变调夹设置会被拒绝。原音音色与合成音色不同，不能以波形相同作为验证目标。

默认指法范围为 0–7 品，范围外的高音会明确计入“未保留音符”；可在高级设置扩大到 12 或 20 品。不会把范围外音符偷偷降八度。扩大范围也可能保留更多被模型误认的泛音，需要听音判断。

“简化分解 / 简化扫弦”保留为重新编配选项，页面明确提示会改写原节奏。Python 本机版仍是这个简化编配工作流，未加入神经网络转录。新版浏览器转录应先选择清晰吉他音轨，用短片段做 A/B 对照，逐音编辑可导入 MusicXML 到打谱软件。普通歌曲混音、人声分离残留、特殊调弦、复杂技巧都可能导致较大误差。

## GitHub Pages 网页版

网站部署目标：`https://cnbright.github.io/guitar_song/`。

网页版是完整静态应用：音频解码、和弦识别、伴奏编配、试听和文件导出都在浏览器中进行，不依赖 Python 服务，不上传用户音频。已完成作品存储在当前浏览器的 IndexedDB 中。支持浏览器能解码的格式，优先使用 MP3、WAV、M4A；提供的 MP4 已在 Chromium 中验证。不同设备、浏览器或清除网站数据后，不会保留原浏览器中的作品。

网站源文件在 `static/`，通过以下命令生成可直接发布的 `docs/`：

```bash
npm ci
npm run build
npm test
```

`docs/` 中包含网页代码、公开预训练模型及其 WASM 运行库，无用户音频、测试样例、凭据或 Python 依赖。所有运行资源均来自本站，不使用第三方推理 API。模型来自 `@spotify/basic-pitch@1.0.1`，依赖完整锁定在 `package-lock.json`，保留 Apache-2.0 等许可与 NOTICE。代码使用相对资源地址，可部署在 `/guitar_song/` 子目录。GitHub 仓库 Settings → Pages → Build and deployment，可选择 **Deploy from a branch → main → /docs**；若使用独立 `gh-pages` 分支，则选择 **gh-pages → /(root)**。

简化模式仍使用 JavaScript FFT chroma 和 Viterbi 和弦识别；Python 版使用 HPSS/CQT。旧版在《爱河》上的小节数、调性和开头和弦匹配，不能证明整曲演奏正确。

本版支持实验性的原吉他音轨转录，以及分解和弦、扫弦的简化编配。将普通歌曲重新编成完整指弹独奏尚未实现。

## 功能

- 上传 MP3、WAV、FLAC、M4A、MP4、WebM 等 FFmpeg 支持的音视频，限制为 100 MB、10 分钟。
- 自动估计速度、起拍、调性与大/小三和弦；选择 4/4 或 3/4 拍，每小节或每半小节识别一个和弦。
- 选择分解和弦或扫弦（民谣律动 / 每拍下扫），生成真实的弦、品位、时值和 MIDI 音高。
- 变调夹 0–12 品，保持原音频音高，自动换算左手指型。根据开放和弦比例推荐 0–7 品位置。
- 显示和弦图、实际响音、六线谱和建议复核标记；点击和弦名称可修改或恢复自动识别。
- 原音对照、合成拨弦试听、小节同步高亮、0.5–1.25 倍速练习。
- 全谱打印 / 浏览器另存 PDF；导出 MusicXML、MIDI、TXT、JSON。
- 刷新后恢复最近作品，可删除作品音轨和分析文件。桌面和手机响应式布局。

## Python 本机版：安装与运行

需要 **Python 3.12**（已测试 3.12.14）和 **FFmpeg / ffprobe**。浏览器建议使用近期版本的 Chrome、Edge 或 Firefox。

### macOS / Linux

先安装 Python 和 FFmpeg。例如 macOS 使用 Homebrew：

```bash
brew install python@3.12 ffmpeg
```

Ubuntu 24.04：

```bash
sudo apt-get update
sudo apt-get install python3.12 python3.12-venv ffmpeg
```

在项目目录运行：

```bash
bash scripts/install.sh
bash scripts/start.sh
```

在浏览器地址栏输入 `http://127.0.0.1:8000`，保留终端窗口。按 `Ctrl+C` 停止。

如果默认 python3 不是 3.12，可使用 `GUITAR_PYTHON=python3.12 bash scripts/install.sh`。不需要 Node.js。

### Windows

安装 Python 3.12（包含 Python Launcher）以及 FFmpeg，并让 `ffmpeg`、`ffprobe` 可以从命令提示符运行。然后双击 `start-windows.bat`。首次启动会安装依赖；按窗口提示在浏览器打开应用。

Windows 启动脚本已提供，本次验证环境为 Linux，尚未在真实 Windows 机器运行。

### 云环境

```bash
cd /workspace/guitar_song
bash scripts/start.sh
```

默认只监听本机。可通过 `GUITAR_HOST` / `GUITAR_PORT` 配置监听地址与端口。此版本是单用户本地应用，没有账号隔离；公开部署前需添加认证、配额与受控上传代理。音频不会被发送到外部识别服务。

每个云任务已隔离，直接使用现有 checkout；无需创建 Git worktree。进程不随环境快照恢复，后续任务需重新执行启动脚本。

## 使用步骤

1. 选择一首歌或带音轨的视频，输入简短名称。
2. 网页版默认选择“原伴奏转录”；只有希望重新编配节奏时才选择“简化分解 / 扫弦”。选择变调夹及拍号。
3. 点击生成。首次分析会初始化音频算法，耗时通常高于后续任务。
4. 参考推荐变调夹，点击“更新我的编配”。数字 0 表示变调夹后的空弦，和弦名称表示手指按的指型。
5. 对照原音试听。若第一拍没对齐，在高级设置调整起拍时间、速度。改变速度、拍号、起点或和弦变化频率会清空原网格上的手动改动并重新识别；改变变调夹或演奏方式会保留手动和弦。
6. 转录模式下，和弦修改只改变标签，不会重写检测音符；需要逐音校对时，请导出 MusicXML。简化模式下，修改和弦会重新编配音符。

**例子：** 实际响音是 Ab，变调夹夹 1 品时，按 G 指型。按 C 指型再夹 2 品，实际响音是 D。软件的音频试听、MIDI 和谱面使用同一组音符，保持这一关系。

## 已上传《爱河》片段的验证

v2 使用用户新提供的 147.12 秒 Instrumental WAV 做了真实浏览器转录、A/B 切换、四种导出、PDF、刷新恢复和移动布局检查。模型推理约 20 秒（本次容器测试），移动设备可能更慢。以独立声学起音检测作参考，旧版固定节奏的起音匹配 F1 约 0.348，新版转录约 0.800（±75ms、一对一匹配）；这是节奏对齐的代理指标，**不是人工标注的音符准确率**，不保证和声、全部音高和弦位正确。

MIDI 校验确认音高与草稿事件一致，最大起音序列化误差小于 1ms；MusicXML 每弦一个声部，跨小节延音用连音线表示。它们验证“导出忠于草稿”，不能证明“草稿忠于录音”。用户音频及试听对照片段不发布到公共仓库。

以下为 v1 的历史功能检查，不能当作准确性证据：

本次使用用户提供的约 147.12 秒 MP4 完成了真实上传与处理。自动估计约 129.2 BPM、Ab 调；推荐变调夹第 1 品，生成 79 小节。开头指型为 `G – D – Em – C – G – Em – Am – D`。

视频中原示范谱包含 D/F♯ 等转位；本版只识别大、小三和弦，因此会简化为 D，低音走向未被原样保留。该样例验证了功能流程，并非整曲逐小节人工校准后的准确率评测。默认小节起点约 0.952 秒仍为估计值。测试文件与用户视频不包含在源码包内。

## 识别方式与边界

Python 版：FFmpeg 提取 22,050 Hz 单声道音轨 → HPSS 减弱打击成分 → CQT chroma 表示和声 → 24 个大/小三和弦模板与 Viterbi 平滑 → 变调夹指型换算 → 固定右手织体编配。

浏览器转录：Web Audio 解码 → Worker 中 TensorFlow.js / WASM 运行 Basic Pitch → 清理缺少声学起音支持的同音碎片 → 保持原始音高与时间并分配弦位 → 试听 / 多声部 MusicXML / MIDI。WASM 关闭多线程，不要求跨域隔离。首次转录需加载本站模型，加载完成后推理无需联网；音频不上传。

- 简化模式无需模型；逐音转录使用公开预训练模型。HPSS 不是人声或吉他分轨，混音仍会干扰结果。
- 简化模式是和弦识别后的新编配。逐音模式检测实际音符，但滑音、击勾弦、特殊调弦与复杂技巧仍不保证正确。
- 七和弦、挂留和弦、转位及复杂和声可能被简化为三和弦。和弦“把握”是相对模板匹配指标，不是校准过的准确率概率。
- 自动节拍存在半速 / 倍速、小节第一拍和随演奏漂移的问题；提供手动 BPM、起点、拍号与和弦校对。
- 标准调弦 E2 A2 D3 G3 B3 E4；六线谱上方为最细的 1 弦。固定指型优先开放和弦，仍可能出现横按。
- 浏览器试听是合成拨弦音色，用于验证音符和节奏，不是录音级的真实吉他音源。

```bash
.venv/bin/python -m pytest -q
node --test tests/browser_engine.test.cjs
npm test
```

测试覆盖真实合成和弦音频识别、24 个和弦的变调夹音高一致性、两种演奏方式、半小节扫弦、休止、3/4 与尾部不完整小节、中文 MIDI、MusicXML 时值、无效音频、完整上传/编配/导出/删除 API。

可选浏览器测试（另外安装 Playwright，并安装 Chromium 或指定系统 Chromium 路径）：

```bash
python scripts/browser_smoke.py --file /path/to/song.mp4 --browser /usr/bin/chromium
```

该脚本使用已运行的服务，验证上传、变调夹、试听、改和弦、扫弦、恢复作品、所有导出、PDF 和手机布局。用户样例可用 `--aihe` 开启特定的预期和弦断言。浏览器依赖不属于应用运行依赖。

结构：

```text
app/audio.py        解码与音频特征
app/arrangement.py  和弦识别、指型与音符编配
app/exports.py      MIDI / MusicXML / TXT 导出
app/main.py         异步任务与 HTTP API
static/            无构建步骤的网页应用
static/engine.js    浏览器音频分析、编配和导出引擎
docs/              可直接部署到 GitHub Pages 的静态站点
tests/             音频、乐理和 API 测试
scripts/           安装、启动与浏览器检查
.data/jobs/        本机作品数据（Git 忽略）
```

依赖完整版本锁定在 `requirements.lock`，直接依赖在 `requirements.txt`。上传任务单 worker 顺序处理，最多排队 4 个；重启中断的任务会标记为失败，已完成的作品可继续打开。`GUITAR_DATA_DIR` 可指定数据目录。删除作品会移除该任务目录；更换上传文件不会自动删除旧作品。
